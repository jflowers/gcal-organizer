# Feature Specification: Support Updated Notes by Gemini Heading and Section Position

**Feature Branch**: `011-next-steps-heading`  
**Created**: 2026-04-16  
**Status**: Draft  
**Input**: User description: "Google's Notes by Gemini changes the position and name of the section in its doc of 'Suggested next steps'. It is now in the middle of the page and the section name changed to 'Next steps'; this breaks being able to assign tasks."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Task Assignment with New "Next Steps" Heading (Priority: P1)

A user runs the task assignment workflow against a meeting notes document generated by the latest version of Notes by Gemini. The document uses the new heading "Next steps" (instead of the previous "Suggested next steps"). The system correctly identifies the section, extracts the checkbox items within it, determines assignees, and assigns them through the browser automation.

**Why this priority**: This is the core broken functionality. Without this fix, zero tasks are extracted from any newly generated meeting notes, making the entire task assignment feature non-functional for current Google Workspace users.

**Independent Test**: Can be fully tested by running `gcal-organizer run` (or `assign-tasks`) against a meeting notes document that uses the "Next steps" heading and verifying that tasks are extracted and assigned.

**Acceptance Scenarios**:

1. **Given** a Notes by Gemini document with a "Next steps" section heading and checkbox items beneath it, **When** the system extracts checkbox items, **Then** all checkbox items in that section are correctly identified and returned.
2. **Given** a Notes by Gemini document with a "Next steps" section heading, **When** the browser automation navigates to the section, **Then** the browser scrolls to the correct "Next steps" heading in the document.
3. **Given** a Notes by Gemini document with a "Next steps" section heading containing three unassigned checkbox items with named individuals, **When** the full task assignment pipeline runs, **Then** all three tasks are assigned to the correct individuals.

---

### User Story 2 - Backward Compatibility with "Suggested next steps" Heading (Priority: P1)

A user runs the task assignment workflow against an older meeting notes document that still uses the original "Suggested next steps" heading. The system continues to work exactly as before.

**Why this priority**: Users have existing meeting notes from past meetings that use the old heading format. Breaking backward compatibility would make historical documents unusable for retroactive task assignment.

**Independent Test**: Can be fully tested by running task assignment against a meeting notes document with the "Suggested next steps" heading and verifying behavior is unchanged.

**Acceptance Scenarios**:

1. **Given** an older Notes by Gemini document with a "Suggested next steps" section heading and checkbox items, **When** the system extracts checkbox items, **Then** all items are correctly identified (same behavior as before this change).
2. **Given** an older document with "Suggested next steps" heading, **When** the browser automation navigates to the section, **Then** the browser scrolls to the correct heading.

---

### User Story 3 - Section Boundary Enforcement (Priority: P2)

A user runs the task assignment workflow against a Notes by Gemini document where the "Next steps" section appears in the middle of the document (not at the end). The system extracts only the checkbox items belonging to that section and does not pick up unrelated bullet items from subsequent sections.

**Why this priority**: With the section now positioned in the middle of the document, failing to enforce section boundaries results in false positives — unrelated bullets from later sections would be incorrectly treated as tasks and assigned to people. This causes user confusion and erroneous task assignments.

**Independent Test**: Can be tested by running extraction against a document where "Next steps" is followed by another headed section containing bullet items, and verifying only the "Next steps" bullets are returned.

**Acceptance Scenarios**:

1. **Given** a document where the "Next steps" section is followed by another section (e.g., "Meeting summary") that also contains bullet items, **When** the system extracts checkbox items, **Then** only the items under "Next steps" are returned; items under subsequent headings are excluded.
2. **Given** a document where the "Next steps" section is followed by a heading at any level (H1 through H6), **When** extraction runs, **Then** the extraction stops at that heading boundary.
3. **Given** a document where the "Next steps" section is the last section (no heading follows), **When** extraction runs, **Then** all remaining bullet items to the end of the document are collected (preserving legacy behavior for documents where the section is still at the end).

---

### User Story 4 - Graceful Handling of Missing Section (Priority: P3)

A user runs the task assignment workflow against a meeting notes document that contains neither a "Next steps" nor a "Suggested next steps" heading. The system handles this gracefully without errors.

**Why this priority**: Not all meeting notes documents will contain a next steps section. The system should degrade gracefully rather than fail.

**Independent Test**: Can be tested by running extraction against a document with no matching heading and verifying no errors are raised and an empty result set is returned.

**Acceptance Scenarios**:

1. **Given** a meeting notes document with no "Next steps" or "Suggested next steps" heading, **When** the system attempts to extract checkbox items, **Then** an empty list is returned with no errors.
2. **Given** a document with no matching heading, **When** browser automation attempts to navigate to the section, **Then** the system logs a warning and skips the document without crashing.

---

### Edge Cases

- What happens when a document contains both "Next steps" and "Suggested next steps" headings? The system should use the first matching heading encountered in document order.
- What happens when the heading text contains extra whitespace or formatting (e.g., bold, italic)? The matching should be case-insensitive and based on the plain text content regardless of formatting.
- What happens when a "Next steps" heading exists but has zero checkbox items beneath it? The system should return an empty list without error.
- What happens when the phrase "next steps" appears in regular body text (not as a heading)? The system should not treat body text occurrences as section headings.
- What happens when the section contains a mix of processed (marked with the idempotency emoji) and unprocessed items? Only unprocessed items should be forwarded for assignment, consistent with existing behavior.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST recognize "Next steps" as a valid section heading for checkbox extraction (case-insensitive matching).
- **FR-002**: System MUST continue to recognize "Suggested next steps" as a valid section heading for backward compatibility (case-insensitive matching).
- **FR-003**: System MUST stop collecting checkbox items when a subsequent section heading is encountered (any heading level), preventing items from unrelated sections from being included.
- **FR-004**: System MUST use the first matching heading encountered in document order when multiple candidate headings exist in the same document.
- **FR-005**: Browser automation MUST attempt to locate the "Next steps" heading first, then fall back to "Suggested next steps" if no match is found.
- **FR-006**: System MUST return an empty result set (not an error) when no matching section heading is found in a document.
- **FR-007**: System MUST log a warning when browser automation cannot locate any matching section heading in a document.
- **FR-008**: Existing idempotency behavior (skipping items marked with the processed emoji) MUST be preserved regardless of which heading name is used.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Task assignment completes successfully on 100% of newly generated Notes by Gemini documents using the "Next steps" heading.
- **SC-002**: Task assignment continues to work on 100% of existing meeting notes documents using the "Suggested next steps" heading (zero regressions).
- **SC-003**: When the next steps section is in the middle of a document, zero unrelated bullet items from subsequent sections are incorrectly extracted as tasks.
- **SC-004**: Documents with no matching section heading are processed without errors, producing zero false task assignments.

## Assumptions

- Google's Notes by Gemini uses standard heading styles (not plain bold/large text) for section headings, making them distinguishable from body text in the document structure.
- The new "Next steps" heading may appear at any position in the document, not only at the end.
- Google may continue to evolve the heading name in the future; the design should accommodate adding new candidate heading names easily.
- The heading text match should be a full heading match (the heading's text content matches a candidate name), not a substring match against arbitrary paragraph text, to avoid false positives on body text that incidentally contains "next steps."
- Older documents that were already processed before this change do not need reprocessing; this fix is forward-looking for new runs.
